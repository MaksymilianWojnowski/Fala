# Fala Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Fala, a local-first PWA for drilling Brazilian Portuguese tenses with FSRS, typed answers and phone↔laptop sync.

**Architecture:** A static Vite + React + TypeScript app that reads generated JSON (verbs, sentences) and hand-written TS content (units, lessons). Progress lives in IndexedDB. A Python pipeline, run by hand, produces the JSON from verbecc, Wiktionary (kaikki.org), Tatoeba and spaCy. A ~50-line Cloudflare Worker stores one JSON snapshot per sync code, and the client merges per card.

**Tech Stack:** React 19, Vite 8, TypeScript, ts-fsrs 5.4, idb-keyval 6, vite-plugin-pwa 2, Vitest 5; Python 3.12, verbecc 2.0.3, spaCy 3.8.16 + `pt_core_news_lg`, pytest; Cloudflare Pages + Workers KV (wrangler).

**Spec:** `docs/superpowers/specs/2026-10-24-fala-design.md`. Mockups: https://claude.ai/artifact/7BZibedhaTxhUL8XnNbxwu. Screen copy, layout and colors follow the mockups unless a task says otherwise.

## Global Constraints

- Brazilian Portuguese only. No `vós`. `tu` is optional and off by default (`settings.tu = false`). The imperative has only the `ele`, `nos` and `eles` cells.
- All UI copy is in English. Every Portuguese string is rendered with `lang="pt-BR"` and the `.pt` class (Newsreader).
- Runtime deps are exactly `react`, `react-dom`, `ts-fsrs`, `idb-keyval`. Dev deps: `vite`, `@vitejs/plugin-react`, `typescript`, `vitest`, `@types/react`, `@types/react-dom`, `vite-plugin-pwa`. The worker's only dev dep is `wrangler`. Add nothing else.
- Pipeline: `verbecc==2.0.3`, `spacy==3.8.16`, `pt_core_news_lg`, `pytest`. Its output JSON is committed. The app never runs Python.
- Colors exactly as in the spec §4.1 token table. Touch targets ≥ 44 px. Focus ring = 2 px `--accent` border + 4 px `--accent-soft` halo. Motion is 150 ms opacity/transform only, and none under `prefers-reduced-motion`. Every answer state shows an icon and text, never color alone.
- FSRS: `fsrs(generatorParameters({ request_retention: 0.9, enable_fuzz: true }))`.
- Defaults: `minutes 10`, `newPerDay 10`, `tu false`, `strictAccents false`, `accentCombos true`, `theme 'system'`, `streak true`.
- "Today" rolls over at **04:00 local time** (affects the new-card cap and the streak).
- A form with alternatives is stored as `'a|b'`. The first one is preferred and displayed. Checking accepts any of them.
- Card ids: `c:{lemma}:{tense}`, `s:{sentenceId}`, `t:{sentenceId}`. Curated sentence ids are negative.
- Sync: code `/^[A-Za-z0-9_-]{22}$/`, body ≤ 5,000,000 bytes.
- Deploy commands publish a public site, so ask the user before running them.

## Spec deviations (this plan wins where they differ)

1. `Unit` has `filter?: 'regular' | 'irregular'` instead of `verbs?: string[]`. Lesson content moves to `src/content/learn.ts`. Contrast sentences are ordinary `Sentence`s with negative ids in `src/content/contrast.ts`, unlocked by the same rule as Tatoeba sentences.
2. Accuracy stats are kept per **prompt** (`eu`, `você`, `a gente`, `nós`, `vocês`, `tu`), not per slot. That lets the heatmap and weak spots separate *a gente* from *você*, as in the mockups.
3. Verb selection checks infinitives from the frequency list against verbecc's known-verb list (`predicted == False`) instead of using spaCy lemmatization, because single words carry no context.
4. Passing placement creates cards for the unit's **top 30 verbs** only, with first reviews spread over 1–14 days. This avoids hundreds of reviews landing on one day. The other verbs arrive later as normal new cards.
5. `CardState` gains `passes` and `introduced`. `Settings` gains `accentCombos`.
6. `mqp_comp` and `perf_comp` are built from *ter* + the participle, so double participles carry through.

## Review Focus

1. **Phone keyboards** capitalize the first letter, add a trailing space or a period. `"Fizemos "` must still count as correct. (Task 4 test; Task 8 input attributes.)
2. **iOS smart punctuation** turns `'` into `’`. `a’` and `a´` must work like `a'`. (Task 5 test.)
3. **Two valid forms** (double participles: *pago/pagado*, *ganho/ganhado*): either one is accepted everywhere. (Task 3 and Task 4 tests.)
4. **App closed or phone locked mid-session:** every answer given so far is already saved. (Task 8 test.)
5. **Studying after midnight:** 00:30 counts as the previous day for the new-card cap and the streak. (Task 6 and Task 8 tests.)

VERBECC_MAP = {'pres': ('indicativo','presente'), 'perf': ('indicativo','pretérito-perfeito'),

PRONOUN_SLOT = {'eu':'eu', 'tu':'tu', 'ele':'ele', 'você':'ele', 'nós':'nos', 'eles':'eles', 'vocês':'eles'}
def strip_pronoun(c: str, pr: str) -> str          # drop tokens equal to pr or in {que, se, quando, por, não}
def normalize_br(tense: str, slot: str, form: str) -> str   # perf + nos: 'ámos' → 'amos'
def compound(ter: dict, estar: dict, ir: dict, lemma: str, participle: str, gerund: str) -> dict
    # mqp_comp = ter.imperf + ' ' + p, perf_comp = ter.pres + ' ' + p (for each alt p, '|'-joined),
    # prog = estar.pres + ' ' + gerund, fut_ir = ir.pres + ' ' + lemma
def conjugate(lemma: str) -> dict
    # {'lemma','participle','gerund','forms': {tense: {slot: form}}, 'irregular': [...], 'predicted': bool}; lru_cache
def irregular_cells(lemma: str, forms: dict, participle: str) -> list[str]
```
- Notes for the implementer:
  - verbecc output = `json.loads(CompleteConjugator(LangCodeISO639_1.pt).conjugate(lemma).to_json())`. Under `moods[mood][tense]` is a list of `{'c': ['eu fiz'], 'pr': 'eu', …}`. Entries with `pr` in `ela`/`elas`/`vós`, or `c == ['-']`, are skipped. `participle = moods['particípio']['particípio'][0]['c'][0]`, gerund likewise. `predicted = data['verb']['predicted']`.
  - The imperative keeps only `ele` (from `você`), `nos` and `eles` (from `vocês`).
  - Aux tables for `compound()` come from a separate cached `simple_forms(lemma)`, so `conjugate('ter')` does not recurse into itself.
  - Irregular rule: the model verb is `falar`/`comer`/`partir` by ending. `pôr` and verbs ending in `-por` have no model, so every cell is irregular. A simple-tense cell is irregular when its first alternative ≠ the model's form with the model stem (`fal`/`com`/`part`) swapped for `lemma[:-2]`. `participle` is irregular when it ≠ stem + `ado`/`ido`/`ido`. `mqp_comp.*` and `perf_comp.*` cells are irregular iff the participle is. Spelling-change verbs (*fiquei*, *cheguei*) come out as irregular cells, and that is intended: learners need to see them.

class Tok: i: int; text: str; lemma: str; pos: str; morph: dict[str, str]; dep: str; head: int; idx: int
def simple_tense(morph: dict[str, str]) -> str | None
    # Ind+Pres pres · Ind+Past perf · Ind+Imp imperf · Ind+Fut fut · Mood=Cnd cond · Sub+Pres subj_pres
    # Sub+Imp subj_imperf · Sub+Fut subj_fut · Mood=Imp imp · VerbForm=Inf with Person inf_pess · else None
def slot_of(morph: dict[str, str]) -> str | None   # (1,Sing) eu · (2,Sing) tu · (3,Sing) ele · (1,Plur) nos · (3,Plur) eles
def find_gap(toks: list[Tok], verbs: dict[str, dict]) -> dict | None   # {'start','end','lemma','tense','slot'}
```
- `find_gap` rules, in order:
  1. Any `VERB`/`AUX` with Person=2 and Number=Sing rejects the sentence (returns None).
  2. For each `VERB` token whose lemma is in `verbs`: an adjacent `aux` child at `i − 1` makes it compound:
     - *ter* (Tense=Imp) + VerbForm=Part → `mqp_comp`
     - *ter* (Pres) + Part → `perf_comp`
     - *estar* (Pres) + Ger → `prog`
     - *ir* (Pres) + Inf → `fut_ir`
     The span runs from aux start to verb end, and the slot comes from the aux morph. Otherwise use `simple_tense`/`slot_of` on the token itself.
  3. Keep a candidate only if the lowercased span ∈ `alternates(table cell)` and the same form does not appear in another tense of that lemma and slot (ambiguous, e.g. *falamos*).
  4. Return the first candidate kept.
